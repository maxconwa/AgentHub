# Avatars Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every agent gets a stored, rerollable 48×48 pixel-chibi look, drawn server-side in the operator-approved poses, shown wherever agents appear.

**Architecture:** A pure Python port of the approved JavaScript generator (`hub/avatar_art.py`) turns `(version, seed, pose)` into a standalone animated SVG. `hub/avatars.py` stores looks, derives each agent's pose from hub state, and the dashboard serves the SVGs at `/ui/avatars/...` behind operator auth and shows them with a Jinja macro.

**Tech Stack:** Python 3.12, FastAPI, SQLite, Jinja2, pytest.

**Spec:** `docs/superpowers/specs/2026-10-21-dashboard-redesign-design.md` (Avatars; Constraints 2–4, 9). Visual reference: the `Poses.dc.html` and `PixelGrid.dc.html` boards on the avatar Design canvas (operator-approved 2026-10-21; no colored backgrounds).

## Global Constraints

- No external or paid service; the generator ships with agenthub and uses only the standard library.
- A look is `(generator_version, seed)` per agent; `GENERATOR_VERSION = 1`; rerolling picks a new seed; old versions stay renderable.
- SVGs contain no agent- or operator-written text (only palette colors and fixed class names), so they can't carry injected markup.
- Served under `/ui/avatars/...` with operator authentication; page CSP stays `img-src 'self' data:`.
- Avatar responses: `content-type: image/svg+xml`, CSP `default-src 'none'; style-src 'unsafe-inline'; frame-ancestors 'none'`, `x-content-type-options: nosniff`, `cache-control: private, max-age=31536000, immutable` (the URL includes version and seed).
- Animations use `steps()` only and stop under `prefers-reduced-motion: reduce`.
- Revoked agents are not shown with a pose (they keep their look in the database).

## Review Focus

1. An agent row from before this migration: it must get a seed in the migration, not a NULL that breaks rendering.
2. Unknown version, unknown pose, non-integer or negative seed in the URL: 404, never a 500.
3. An agent token (or forged operator headers from an agent device) fetching an avatar URL: 403, like every `/ui` route (the route-walk test must include the new routes).
4. Sixty avatars on one page: the render is cached, so a page reload doesn't re-run the generator sixty times.
5. Pose precedence when several states hold at once (e.g. a running session with a pending permission approval shows *needs you*).

### Task 1: Generator port (`hub/avatar_art.py`)

**Files:** Create `src/agenthub/hub/avatar_art.py`, `tests/test_avatar_art.py`.

**Interfaces — Produces:**
- `GENERATOR_VERSION: int = 1`, `VERSIONS: frozenset[int] = frozenset({1})`
- `POSES: tuple[str, ...] = ("idle", "working", "reviewing", "needs_you", "waiting", "talking", "part_done", "recharging", "error", "offline", "janitor")`
- `POSE_LABELS: dict[str, str]` — `idle: "idle"`, `working: "working"`, `reviewing: "reviewing"`, `needs_you: "needs you"`, `waiting: "waiting on an agent"`, `talking: "talking it over"`, `part_done: "part done"`, `recharging: "recharging"`, `error: "something went wrong"`, `offline: "offline"`, `janitor: "janitor at work"`
- `render_svg(version: int, seed: int, pose: str, *, scene: bool = True) -> str` — a complete `<svg xmlns=… viewBox="0 0 48 48" shape-rendering="crispEdges">` document with an embedded `<style>` (keyframes + reduced-motion) and one `<g class="…">` per layer. `scene=False` drops scene layers (the list-size, character-only version). Raises `ValueError` for an unknown version or pose, or a seed outside `0 <= seed < 2**32`.
- `new_seed() -> int` — `secrets.randbelow(2**31)`.

The port follows the JS on `Poses.dc.html` exactly: same `rng` (Mulberry-style with `Math.imul` → 32-bit masked multiply), same palettes, parts, props, outline pass, greyscale for offline, row-run path encoding. Layer transforms use `transform-box: view-box` with origins in viewBox px.

- [ ] Tests: deterministic (same args → same string); different seeds → different output; every pose renders for 50 seeds; `scene=False` output is shorter and has no scene-only colors (e.g. the cushion `#8fa3d9`); offline output contains no saturated colors (every fill is grey: r≈g≈b within 8); `ValueError` for version 2, pose `"dancing"`, seed `-1` and `2**32`; output contains no `<script`, no `href`, and a `prefers-reduced-motion` block.
- [ ] Implement; parity check by hand against the JS in node for 3 seeds × 11 poses (path data identical); commit.

### Task 2: Stored looks and pose derivation (`hub/avatars.py`, migration 7)

**Files:** Modify `src/agenthub/hub/db.py` (migration 7), `src/agenthub/hub/store.py` (agent insert); create `src/agenthub/hub/avatars.py`, `tests/test_avatars.py`.

**Interfaces — Produces:**
- Migration 7: `agents.avatar_version INTEGER NOT NULL DEFAULT 1`, `agents.avatar_seed INTEGER NOT NULL DEFAULT 0`, then `UPDATE agents SET avatar_seed = abs(random()) % 2147483648`.
- New agents get `avatar_seed = avatar_art.new_seed()` at insert.
- `avatars.reroll(conn, agent_id: str, *, actor: str) -> dict` → `{"version", "seed"}`; sets `GENERATOR_VERSION` and a new seed; emits `agent.avatar_changed` `{agent_id, version, seed}`; `NotFound` for an unknown agent.
- `avatars.poses(conn, now: datetime | None = None) -> dict[str, str]` — agent id → pose for every non-revoked agent. Precedence, first match wins:
  1. `offline` — `agents.connected = 0`
  2. `needs_you` — a pending approval with `requester = agent id`
  3. `recharging` — a `task_agents.paused_until` later than now
  4. `working` / `reviewing` — an active run (`task_runs.ended_at IS NULL`); `reviewing` if that member's stage is `reviews`
  5. `waiting` — a pending, unexpired ask `from_agent = agent id`
  6. `error` — the agent's latest ended run has outcome `error` and its task is not `done`/`cancelled`
  7. `part_done` — a `works` membership with `finished_at` set on a task in `in_progress` or `review`
  8. `idle`

  `talking` and `janitor` are drawn now but derived in later plans (messaging, janitor).
- `avatars.url(agent: dict, pose: str, *, scene: bool) -> str` → `/ui/avatars/{version}/{seed}/{scene|mini}/{pose}.svg`.

- [ ] Tests: each precedence rule (one test per row, plus needs_you beating working); migration gives pre-existing rows distinct non-NULL seeds; reroll changes the seed and emits the event; new enrollments get a seed.
- [ ] Implement; commit.

### Task 3: Serving and showing avatars (dashboard)

**Files:** Modify `src/agenthub/hub/dashboard.py`, `templates/_macros.html`, `templates/agents.html`, `templates/task.html`, `templates/approval.html`, `templates/approvals.html`, `static/app.css`, `tests/test_dashboard.py`; README (one line).

**Interfaces — Produces:**
- `GET /ui/avatars/{version}/{seed}/{kind}/{pose}.svg` (Op) — `kind ∈ {scene, mini}`; renders via an `lru_cache(maxsize=4096)` wrapper of `render_svg`; 404 for anything `render_svg` rejects or a bad `kind`; headers from Global Constraints.
- `POST /ui/agents/{agent_id}/avatar` (PostOp) — reroll, then redirect to `/ui/agents#agent-{id}`.
- Jinja macro `avatar(ag, pose, size=48, scene=False)` → `<img class="avatar" src=… width height alt="{name}, {pose label}" loading="lazy">`; CSS `.avatar { image-rendering: pixelated; }`.
- Agents page: each card shows the scene avatar at 96 px and a **Reroll look** button. Task page members, approval pages (requester) show the mini avatar at 32 px.

- [ ] Tests: route-walk fixture fills `version/seed/kind/pose`, so agent tokens get 403 on the new routes; operator GET returns 200 with the exact headers; 404 for version 2, pose `dancing`, kind `huge`, seed `-1`; reroll POST without CSRF is refused, with CSRF changes the seed; agents page HTML contains the avatar `<img>` with the right pose for a connected idle agent and for an offline one; revoked agents get no avatar img.
- [ ] Implement; full suite green; commit and push.
