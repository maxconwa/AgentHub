# Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace today's dashboard layout with the eight operator-approved pages (Dashboard, Projects, Tasks, Agents, Devices, Approvals, Chats, Reports), the project/task/agent detail pages with message boards and notes, chatting with an agent, and the ask-the-operator tool.

**Architecture:** Read-side queries for the new pages live in a new pure module `hub/views.py` (dicts in, dicts out, no HTTP). Routes stay in `hub/dashboard.py` (operator auth on every route, CSRF on every POST), templates in `hub/templates/`. Live updates use HTMX polling of a read-only `#live` region on each page (no forms inside it). Questions to the operator are a new `questions` table surfaced in the approval queue.

**Tech Stack:** Python 3.12, FastAPI, SQLite, Jinja2 + HTMX 2.0.11 (vendored), pytest.

**Spec:** `docs/superpowers/specs/2026-10-21-dashboard-redesign-design.md` — "Pages across the top", "Several agents per task", "Detail pages", "Talking to agents from anywhere" (Post only), "Agents can ask the operator", Constraint 5, Calls 14. Visual reference: the operator-approved mockup https://claude.ai/artifact/9KveuCTmtWcFZUwz5JFeVG (its generator script and CSS are handed to implementers with the task brief).

**Not in this plan (later plans):** *Prompt* (waking agents) and the multi-agent split; device CPU/GPU metrics and the usage panel; reports content; the janitor; creating agents from the dashboard. Pages for those show an empty state that says what will appear, never fake data.

## Global Constraints

- Every `/ui` route requires the operator (existing `Op`/`PostOp` dependencies); the route-walk test in `tests/test_dashboard.py` must cover every new route (extend the `world` fixture's `ids` with every new path parameter).
- Responses use `SECURITY_HEADERS`; no inline `<script>`, no inline `style=""` attributes (CSP `style-src 'self'`); new CSS goes in `static/app.css`.
- Agent-written text (messages, task titles/bodies agents wrote, questions, checkout paths, verdict notes) is autoescaped and shown inside the existing `agent_text` macro or labeled "agent text"; never rendered as HTML.
- Operator-written text (descriptions, notes, roles, answers) is stored with author `operator.actor` (`human:<login>`); agents can't produce that author because the hub derives authors from tokens.
- Mobile-first, and works at phone (≤ 600px), iPad (600–1100px) and desktop widths with touch, mouse and keyboard; no horizontal page scroll at 360px; the top bar scrolls sideways on phones.
- Top bar order, exact labels: Dashboard, Projects, Tasks, Agents, Devices, Approvals, Chats, Reports; the Approvals link keeps the polling red badge; a search field submits to `/ui/search`.
- `/ui` and `/ui/` redirect (303) to `/ui/dashboard`.
- Task boards are project channels named `task-<id>`; project boards are the channel `general`; the operator dialogue with an agent is the channel `operator`.
- Live regions poll every 10 s: `hx-get="<the page's own URL>" hx-select="#live" hx-target="#live" hx-swap="outerHTML" hx-trigger="every 10s"`.

## Review Focus

1. Agent-written text on any new page shown without escaping or without its "agent text" label (checkout paths and questions are new sources).
2. An agent token, or forged operator headers from an agent device, reaching any new route, or an agent posting a message that displays as the operator's.
3. Empty hub (no projects, agents, tasks, devices, chats): every page renders 200 with an empty state.
4. A long agent name, task title or checkout path at 360px wide: wraps, no horizontal scroll.
5. A half-typed note or chat message survives the 10 s live refresh (forms sit outside `#live`).

### Task 7: Ask the operator

**Files:** Modify `hub/db.py` (migration 10), `hub/app.py` (API), `client.py`, `mcp_server.py`, `hub/avatars.py`, `hub/notify.py`, `hub/dashboard.py`, `templates/approvals.html`, `templates/dashboard.html`; create `hub/questions.py`, `templates/question.html`, `tests/test_questions.py`.

**Interfaces — Produces:**
- Migration 10: `questions(id INTEGER PRIMARY KEY, project TEXT NOT NULL REFERENCES projects(name), agent_id TEXT NOT NULL REFERENCES agents(id), task_id INTEGER REFERENCES tasks(id), question TEXT NOT NULL, status TEXT NOT NULL CHECK (status IN ('pending','answered','withdrawn')), answer TEXT, answered_by TEXT, created_at TEXT NOT NULL, answered_at TEXT)` + index on `(status, id)`.
- `questions.ask(conn, agent, *, project, question, task_id=None) -> dict` (agent must be allowed in the project; question 1–4000 chars; at most 5 pending per agent, else `Conflict`; emits `question.asked`); `questions.answer(conn, qid, *, answer, actor) -> dict` (emits `question.answered`; posts the answer as `store.post_message(author=actor, project=…, channel="operator", to=<agent>, body="Answer to your question #N: …")`); `questions.withdraw(conn, qid, agent)`; `questions.pending(conn) -> list[dict]`; `questions.get(conn, qid)`.
- API: `POST /api/v1/projects/{project}/questions` `{question, task_id?}` → 201; `GET /api/v1/questions/{id}` (own only, else 404); `POST /api/v1/questions/{id}/withdraw`.
- MCP tool `ask_operator(project: str, question: str, task_id: int | None = None) -> str` — returns at once: "Asked the operator (question #N). The answer will arrive in your inbox, addressed to you." Docstring says to use it when only the operator can decide.
- Approval queue, Dashboard "Waiting on you", and the badge count include pending questions (kind label "Question"); `GET /ui/questions/{qid}` shows the question (agent text) with an answer form; `POST /ui/questions/{qid}/answer` (`answer` 1–4000).
- `avatars.poses`: a pending question makes the agent `needs_you` (same precedence row as approvals).
- ntfy: `question.asked` notifies like `approval.requested` (title "Question · #N", body the agent's name only unless `ntfy_include_details`).

- [ ] Tests: ask/answer round trip (answer appears in the agent's inbox addressed to it, author `human:…`); not allowed in project → 403; sixth pending → 409; another agent can't read or withdraw it; pose `needs_you` while pending; badge counts it; answer form needs CSRF; MCP tool via in-process `mcp.Client`; notification has no question text by default.
- [ ] Implement; commit.

### Task 8: Chats

**Files:** Modify `hub/views.py`, `hub/dashboard.py`, `mcp_server.py` (instructions text), `templates/agent.html`, `static/app.css`; create `templates/chats.html`, `templates/chat.html`; tests in `tests/test_pages.py`.

**Interfaces — Produces:**
- `views.chats(conn) -> dict` with groups, each item `{key, title, last_body, last_ts, avatars}`, newest first:
  - `with_you`: one per agent with any message in channel `operator` (authored by the agent, or by a human with `to_agent` = that agent), key `agent-<agent_id>`;
  - `between_agents`: one per unordered agent pair with an addressed message (`to_agent` set, both agents) or an ask between them, key `pair-<a>-<b>` (ids sorted);
  - `boards`: one per channel other than `operator`, key `board-<project>-<channel>`;
  - plus a fixed `activity` item linking to `/ui/activity`.
- `views.chat(conn, key) -> dict` — `{title, messages: [...], post: {project choices, channel, to} | None}`; 404 for an unknown or malformed key. Pair chats are read-only for the operator (post is None).
- `GET /ui/chats` (list; on wide screens the newest chat opens beside it) and `GET /ui/chats/{key}` (one chat full page, its messages in `#live`, the form outside); `POST /ui/chats/{key}` posts: agent chat → channel `operator`, `to` = agent, project chosen from the agent's allowed projects (default: its current task's project); board → that channel.
- The agent page's pinned dialogue renders `views.chat(conn, f"agent-{id}")`.
- MCP instructions gain one line: "To reply to the operator, `post` in channel `operator`."
