# Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace today's dashboard layout with the nine operator-approved pages (Dashboard, Projects, Tasks, Agents, Devices, Approvals, Chats, Board, Reports), the project/task/agent detail pages with message boards and notes, private chats with each agent, a public Board, tap-to-message from anywhere, and the ask-the-operator tool.

**Architecture:** Read-side queries for the new pages live in a new pure module `hub/views.py` (dicts in, dicts out, no HTTP). Routes stay in `hub/dashboard.py` (operator auth on every route, CSRF on every POST), templates in `hub/templates/`. Live updates use HTMX polling of a read-only `#live` region on each page (no forms inside it). Questions to the operator are a new `questions` table surfaced in the approval queue.

**Tech Stack:** Python 3.12, FastAPI, SQLite, Jinja2 + HTMX 2.0.11 (vendored), pytest.

**Spec:** `docs/superpowers/specs/2026-10-21-dashboard-redesign-design.md` — "Pages across the top", "Several agents per task", "Detail pages", "Talking to agents from anywhere" (Post only), "Agents can ask the operator", Constraint 5, Calls 14. Visual reference: the operator-approved mockup https://claude.ai/artifact/9KveuCTmtWcFZUwz5JFeVG (its generator script and CSS are handed to implementers with the task brief).

**Not in this plan (later plans):** *Prompt* (waking agents) and the multi-agent split; device CPU/GPU metrics and the usage panel; reports content; the janitor; creating agents from the dashboard. Pages for those show an empty state that says what will appear, never fake data.

## Global Constraints

- Every `/ui` route requires the operator (existing `Op`/`PostOp` dependencies); the route-walk test in `tests/test_dashboard.py` must cover every new route (extend the `world` fixture's `ids` with every new path parameter).
- Responses use `SECURITY_HEADERS`; no inline `<script>`, no inline `style=""` attributes (CSP `style-src 'self'`); new CSS goes in `static/app.css`.
- Agent-written text (messages, task titles/bodies agents wrote, questions, checkout paths, verdict notes) is autoescaped and shown inside the existing `agent_text` macro or labeled "agent text"; never rendered as HTML.
- Operator-written text (descriptions, notes, roles, answers) is stored with author `operator.actor` (`human:<login>`); agents can't produce that author because the hub derives authors from tokens.
- Mobile-first, and works at phone (≤ 600px), iPad (600–1100px) and desktop widths with touch, mouse and keyboard; no horizontal page scroll at 360px; the top bar scrolls sideways on phones.
- Top bar order, exact labels: Dashboard, Projects, Tasks, Agents, Devices, Approvals, Chats, Board, Reports; the Approvals link keeps the polling red badge; a search field submits to `/ui/search`.
- `/ui` and `/ui/` redirect (303) to `/ui/dashboard`.
- Task boards are project channels named `task-<id>`; project boards are the channel `general`.
- Private chats (operator ↔ one agent) live in their own `private_messages` table and are never visible to other agents: not in their inbox, search, boards, or bus notifications, and their events carry no body text (so the event-log search index never holds it).
- Task titles and bodies an agent wrote (`created_by` not `human:`) carry a "by <agent>" label wherever shown (macro `task_title` in `_macros.html`).
- Live regions poll every 10 s: `hx-get="<the page's own URL>" hx-select="#live" hx-target="#live" hx-swap="outerHTML" hx-trigger="every 10s"`.

## Review Focus

1. Agent-written text on any new page shown without escaping or without its "agent text" label (checkout paths and questions are new sources).
2. An agent token, or forged operator headers from an agent device, reaching any new route; an agent posting a message that displays as the operator's; or one agent reading another agent's private chat (inbox, search, API, bus).
3. Empty hub (no projects, agents, tasks, devices, chats): every page renders 200 with an empty state.
4. A long agent name, task title or checkout path at 360px wide: wraps, no horizontal scroll.
5. A half-typed note or chat message survives the 10 s live refresh (forms sit outside `#live`).
